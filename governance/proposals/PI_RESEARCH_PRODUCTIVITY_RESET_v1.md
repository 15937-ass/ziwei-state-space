# PI 级研究效率与知识生产导向调整提案 v1.0

- 提案 Issue：[#947](https://github.com/15937-ass/ziwei-state-space/issues/947)
- 状态：**PROPOSAL_ONLY / AWAITING_PI_DECISION**
- 性质：研究路线与工作组织方式调整；不是新的知识理论，不是语义授权，也不是代码/运行时变更。
- 适用范围：Knowledge Palace shards、Knowledge Core、Product 及三线恢复入口。
- 当前约束：本提案未获明确批准前，现行控制文件、Issue 顺序、WIP、Human Gate 和执行权限继续有效。

## 1. 提案摘要

建议把项目的主要工作方式，从：

> 按局部语义缺口持续拆分工单、审计、分类、建立状态和等待审批

调整为：

> 围绕有解释力的紫微斗数理论问题组织研究；AI 完成来源阅读、跨材料比较、案例重建和候选解释；PI 决定真正影响整体理论的关键问题；研究结果再按现有质量标准进入知识库。

这不是取消工程治理，而是**降低治理在日常研究中的占比**。来源追溯、原文核验、学派隔离、未知状态、路径所有权、质量门和串行集成继续保留。

本提案要求的变化只有四类：

1. 工作单元由“一个局部缺口”转为“一个有边界的主题研究包”。
2. 研究交付由“审计完成情况”转为“知识发现、案例重建、理论解释及其证据边界”。
3. 宫位线进行两个不同宫位并行槽位的有限试点，不提高现有 G12 硬上限。
4. Core 在当前 C9 结束后，优先开展六十星系验证与代表性案例重建，而不是自动继续零散语义审计。

Product 不为追求并行而制造填充任务。

## 2. 为什么需要调整

### 2.1 项目已经有足够多的知识原材料

以下是仓库中已经存在的、范围明确的成果：

| 模块 | 已有成果 | 正确理解 |
|---|---|---|
| WP02 十四正曜 | 430 条 reviewed rules | 相对于《中州派紫微斗数深造讲义（上）》十四正曜章节的抽取完成，不代表所有中州派来源均已穷尽 |
| WP03 六十星系 | 60/60 个系统、2193 条规则 | 全文抽取完成，但全局验证仍为 VALIDATION_PENDING |
| WP06B/WP06C | 15 个 canonical nodes、15 条 canonical mappings | 已有正式知识映射检查点，不代表全部可执行或 Product 已获消费授权 |
| 十四主星专项研究 #757 | 250 条 source claims、182 项候选、241 项目标审核记录 | 研究交付已接受，但候选性质仍不是自动晋升的 canonical 星核 |
| WP05 十二宫 | 多个宫位已有大量来源记录和历史审查 | 不同宫位的来源覆盖、canonical revalidation、案例支持和可执行程度不能混为一谈 |

关键依据：
- [WP02 十四正曜抽取报告](../../validation/KB_WP02_十四正曜完整抽取报告.md)
- [WP03 六十星系总审查](../../validation/KB_WP03_六十星系总审查.md)
- [Core continuation plan #901](https://github.com/15937-ass/ziwei-state-space/issues/901)
- [十四主星研究 #757](https://github.com/15937-ass/ziwei-state-space/issues/757)

这些成果已经足以支持更有价值的下一步：验证规则能否组合成作者实际使用的推理链，比较单星、星系、宫位和时间条件之间的关系，并用教材案例检查解释是否成立。

### 2.2 近期 Core 工作出现局部问题连续拆分的倾向

C4–C9 连续处理了冲起/冲会、吉曜/煞曜、火铃同度、否定语义、持续性与路径等问题。这些研究本身有价值，也确实解决了若干来源边界。

但它们反映出一个组织风险：相互关联的术语和条件容易被拆成多个独立工单，每轮都重新建立局部背景和交接；项目可能持续提高语义审计的精细程度，却没有同步提高整体推演解释能力。

本提案不否定这些研究，也不要求撤销已接受结果。调整的是**后续任务的选择方式**：只有当局部缺口真实阻塞重要理论链条、共享契约或安全消费时，才优先单独立项；其他相关问题并入更大的主题研究包。

### 2.3 宫位线的实际并行度低于已批准的架构上限

现有 G12 架构允许最多四个不同宫位 worker，每宫最多一个；但 #676 的 PI 选择把实际运行收紧为一次只推进一个宫位。

这一安排有利于初期控制复杂度，但它也让不同宫位之间本来可以独立进行的来源研究长期等待。可以通过小规模试点检验：两个宫位并行是否能提高有效产出，而不增加来源冲突、重复劳动和合并风险。

### 2.4 PI 的时间应更多用于理论判断

PI 不应逐条审批常规来源转录、字段补齐或普通局部分类。PI 最有价值的工作是判断：

- 单星本质和星系本质之间是什么关系；
- 星曜之间的关系是否具有可推广的共同结构；
- 宫位条件怎样改变同一星系的表现；
- 原局、大限、流年如何发生有条件的相互作用；
- 某种理论解释是否符合指定学派的原文和案例。

AI 应把这些问题整理成有来源、有反例、有不同解释的决策材料，而不是把 PI 变成工单审批员。

## 3. 新的研究工作单元：主题研究包

### 3.1 基本原则

一个研究 Issue 围绕一个**有明确来源范围、理论目标和验收产物的核心问题**组织。一个主题可以包含若干紧密相关的子问题；不再要求每个局部术语、每个 GAP 或每条规则都建立一个独立工单。

允许合并的条件：
- 属于同一理论主题或同一条推理链；
- 共享主要来源、案例或上下文；
- 能由同一组交付物和验收标准判断完成；
- 不跨越未经授权的路径所有权或语义权限。

不允许为了减少 Issue 数量，把无关问题强行塞进一个大工单。研究包仍须可恢复、可验证、可交接。

### 3.2 每个主题研究包必须交付什么

每轮至少完成以下五类产物中的适用项：

1. **来源证据**：准确来源、页码、原文条件、适用对象、时间层级和限定词。
2. **结构化发现**：规则之间的关系、共同模式、差异条件、前提和例外。
3. **对照与反例**：相似文本、相反案例、不支持的推论，以及为什么不能推广。
4. **理论综合**：提出可解释材料的候选结构；明确它是来源明文、保真归一化还是研究假说。
5. **未决问题**：保留未知项、来源冲突、缺失前提及其影响；只把真正需要 PI 决策的问题单独列出。

研究结论可以是“没有足够证据支持统一规律”，但不能只交付一串 HOLD/UNKNOWN 而不说明已经检查了什么、排除了什么、为什么不能推广。

### 3.3 推荐的工作尺度

- 约 30–50 个来源片段可作为一次内部阅读/比较子批次，按章节和语义密度调整。
- 约 100 条仍可作为常见的来源审查持久检查点上限，但不是必须凑满的配额。
- 案例重建、跨星系比较和理论综合按完整推理链组织，不受“每批必须多少条”的机械限制。
- 若一个问题需要更多材料，拆成有明确依赖的阶段；若少量材料已足以回答，不得为了达到数量而重复抽取。

现有来源优先、原扫描核对、唯一 ID、条件保真和精确交接要求继续有效。

## 4. 知识结论的证据层级

为防止 AI 把“发现规律”误当成“理论已经成立”，统一区分以下层级：

| 层级 | 名称 | 可以做什么 | 不可以做什么 |
|---|---|---|---|
| S1 | 来源明文主张 | 保存原文明确表达的性质、条件、关系和断语 | 把来源没有说的条件补进去 |
| S2 | 保真归一化 | 用结构化字段表达来源原意，保留限定、例外和不确定性 | 改变来源强度、对象或适用范围 |
| S3 | 研究综合假说 | 比较多个来源、星系或案例，提出共同解释和可反驳预测 | 自动写成 canonical 真理或通用算子 |
| S4 | PI 接受的理论结构 | 在证据、反例和学派边界明确后，接受或拒绝某项整体理论解释 | 越过现有 Human Gate 或省略正式记录 |
| S5 | 可执行知识契约 | 在明确字段、前提、冲突和失败路径后供实现层消费 | 因“理论上合理”而自动授权 Product/runtime |
| S6 | 经验校准结果 | 在独立数据和适当方法下评估现实表现 | 反向篡改传统来源，或把相关性说成因果 |

**AI 可以自主提出 S3 候选，但不得自行把 S3 晋升为 S4、S5 或 S6。**

S1/S2 的普通来源工作，在现有契约和路径权限内继续自主推进；只有涉及共享理论结构、不可保留的传统语义冲突、学派边界、执行授权或经验因果主张时才交 PI。

### PI 决策卡

需要 PI 决定的问题，必须以中文决策卡呈现，且包含：

- 问题的紫微斗数含义；
- 最直接的原文依据和上下文；
- 至少两个可区分的解释（若确实存在）；
- 每种解释的支持证据、反例和影响范围；
- AI 的推荐意见及理由；
- 如果暂不决定，能否安全保留 UNKNOWN 并继续其他工作。

常规工作不要求 PI 逐行签字。每个研究检查点原则上只汇总 1–3 个真正影响整体理论的决策；没有此类问题时明确写“本轮无待 PI 决策”。

## 5. 宫位线：两个并行槽位试点

### 5.1 试点范围

建议将宫位线的实际运行上限从“同时一个宫位”暂时调整为：

- 同时最多 **两个不同宫位**；
- 每个宫位最多一个 ACTIVE work unit；
- Core 仍最多一个 ACTIVE work unit；
- 不修改 G12 原有硬上限：宫位总数仍不超过四个、每宫不超过一个；
- 最终合并仍由 #888 Integration Lease 串行控制。

这是一个有退出条件的试点，不是永久提高并行度，也不是同时启动所有宫位。

### 5.2 准入规则

第二个宫位只有同时满足以下条件才可启动：

1. 先完成实时 Issue/PR、分片状态、来源依赖和写集核对；
2. 与第一个宫位属于不同 shard，不共享同一组待修改文件；
3. 不依赖第一个宫位尚未合入的分支内容；
4. 具有明确、可直接开始的来源范围和验收产物；
5. Core gap 在本宫位保持 fail-closed，不在宫位侧自行定义共享语义；
6. 当前没有其他宫位占用第二槽。

如果没有合适的第二项工作，第二槽可以空着；**不为了追求并行而制造填充任务。**

### 5.3 当前候选如何处理

本提案记录的 2026-10-30 快照：

- P04 #943 / PR #944 已完成本批来源研究，处于 READY_TO_INTEGRATE；不打断、不重做。
- P06 #773 当前为 WAITING_SEQUENCE，具有明确来源范围和历史材料，可以在本提案获 PI 批准后，作为第二宫位槽位的优先候选重新核对。
- 如果 #943 在试点启动前已经合入并释放槽位，则不强行制造并行；按最新 live Issue、依赖和来源覆盖情况重新选择两个可独立工作的宫位。

P06 涉及的疾病、诊断、手术等传统文本必须继续保持原有认识论边界，不转成现代医学诊断、治疗或现实预后结论。

### 5.4 试点退出条件

完成两个宫位检查点并合入 main 后评估：

- 是否减少了宫位线等待；
- 是否产生跨宫位重复审查或语义冲突；
- 是否增加了集成排队和返工；
- 两个宫位的来源质量、条件保真和验收质量是否保持；
- PI 是否因此承担了更多而非更少的协调工作。

若出现重复劳动、跨宫位写集冲突或明显返工，退回一个宫位槽位；已接受成果保留，不回滚知识内容。

## 6. Knowledge Core：从零散审计转向整体解释能力

### 6.1 当前 C9 的处理

当前 Core C9（#945 / PR #946）按原有范围完成和收尾，不因本提案扩大任务、不撤销已完成来源研究，也不把当前 PR 的技术问题转化成新的理论研究。

当前 PR 曾因 Knowledge-only 分支修改 Governance 所有权测试文件而触发路径所有权失败。该问题应按正确 owner 和现有治理规则解决，不能通过放宽路径所有权来换取速度。今后 Knowledge 工单不得自行修改 Governance-owned 测试。

**C9 结束后，不自动开启 C10、C11、C12 式的零散审计链。** 新 Core 工作应根据整体理论收益重新排序。

### 6.2 下一优先候选：WP03 验证 + WP06A 案例重建试点

建议下一 Core 主题研究包暂定为：

**六十星系结构验证与教材案例推理链重建试点。**

现有基础：
- 六十星系已有 60 个 principal mode、2193 条规则，抽取完成但验证待完成；
- WP03 总审查列出 81 条明确 case_evidence 和 149 条 case_level 记录；
- WP02 十四主星已有 430 条来源规则；
- WP06A 的目标本来就是重建教材案例、作者 claim、reasoning 和规则链接。

首轮采用小规模、可复核的试点，不声称完成整个 WP03/WP06A：

1. 先对现有 case_evidence 和来源完整度做一次轻量清点。
2. 按结构多样性、来源完整度和可重建性，选择约 3 个代表性星系；不预先虚构具体系统编号。
3. 从来源条件足够的材料中选择约 6–10 个教材案例；如果满足条件的案例不足，就按实际数量开展，不为凑数降低标准。
4. 逐例重建作者推理链：
   - 命盘和相关星曜事实；
   - 单星性质与星系本质；
   - 辅佐煞化和结构修饰；
   - 宫位/三方四正/跨宫上下文；
   - 大限、流年等时间条件；
   - 作者最终断语及其限定。
5. 对每一步标记：来源明文、保真归一化、合理但未证实的推断、缺失前提、冲突或无法重建。
6. 比较不同案例，寻找可复用的结构和反例；只提出候选理论，不自动建立 universal operator 或数值权重。

### 6.3 首轮必须交付

- 代表性星系验证报告；
- 案例重建表，每一步都可回溯来源；
- 作者推理链中可复现与不可复现的环节；
- 跨案例共同结构、差异条件和反例；
- 当前规则库缺失的真实知识缺口；
- 值得 PI 决定的理论问题；
- 下一轮建议：扩展案例、扩展星系、回到来源审计，或保留未决。

验收不以“全部解释成功”为条件。正确发现某个教材案例缺少关键前提，或某种看似共通的规律被反例否定，同样是有效研究成果。

### 6.4 后续 Core 任务选择原则

首轮试点后，按以下顺序评估候选：

1. 是否能解释多个星系、宫位或时间层的真实材料；
2. 是否有足够直接来源和可对照案例；
3. 是否能检验、反驳或区分不同理论解释；
4. 是否解除重要的跨模块依赖；
5. 工作范围是否可以在一个 Core WIP 内完成。

WP07B 仍然重要，但后续只有在它直接阻塞重要推理链、产品消费契约或多个宫位工作时才优先单独立项。普通术语差异可并入相应主题包，安全可保留的 UNKNOWN 不要求立即清零。

十四主星 #757 已接受的专项研究不自动重开；只有出现新来源、新反例或案例重建证明现有结论存在实质缺陷时才重新审查。

## 8. 治理和质量控制：保留硬门槛，减少重复行政动作

### 8.1 继续保留的控制

以下内容不在本提案的削减范围内：

- 原始来源和扫描页核验；
- 学派/来源隔离；
- 来源明文、推断、假说的区分；
- 条件、前提、否定、时间层级、反例和 UNKNOWN；
- 每个 shard 的写集所有权；
- Core/Product/宫位的 WIP 上限；
- #888 Integration Lease；
- 合并前 exact-head 全量质量门；
- Product 消费授权、运行时授权和经验有效性边界。

### 8.2 应减少的重复动作

- 不为每个局部 GAP 都建立独立 Governance Issue。
- 不为同一批来源材料重复建立相同背景报告；用版本和变更摘要定位需要重读的部分。
- 不在 ACTIVE_BUILD 阶段因无关 main 变化反复运行最终全量门；按现行协议在准备集成并取得 Lease 后执行最终 exact-head gate。
- 不把“文件数、测试数、Issue 数”作为研究成果本身。
- 不为了让状态缓存看起来完整而跨 lane 修改其他 owner 的文件。
- 同一批来源核对、条件核对、数量核对和时间层级检查应尽可能合并为一次研究流程，但分别保留各自结论。

### 8.3 一个研究 Issue 的最小合同

每个研究 Issue 只需明确：

1. 核心研究问题和范围；
2. 必须使用的来源/案例及页码；
3. 允许修改的路径；
4. 必须交付的知识成果；
5. 必须检查的反例和负边界；
6. 验收标准；
7. 不得越过的语义、学派、Product 和经验边界；
8. 下一步交接条件。

只有发生真实跨模块权限、架构或优先级冲突时，才单独启动 Governance work unit。

### 8.4 质量门不降级

本提案不缩小最终验收范围、不跳过测试、不允许旧绿灯替代新 head 验证。仍然遵守：

ACTIVE_BUILD 独立研究与有界验证 → READY_TO_INTEGRATE → #888 Integration Lease → 同步最新 main → exact-head 全量质量门 → 合并 → 释放 Lease。

## 9. PI 汇报方式调整

每轮汇报应优先回答：

1. **本轮真正弄明白了什么？** 用普通中文解释理论发现。
2. **证据在哪里？** 给出来源、页码、案例和条件。
3. **什么情况不支持这个解释？** 给出反例、边界和未决项。
4. **它对整体体系有什么影响？** 说明与单星、星系、宫位、四化、时间层的关系。
5. **需要 PI 决定什么？** 只呈现真正影响理论方向的少量问题；没有则明确说明。
6. **下一步最值得做什么？** 给一个优先建议，而不是长篇工单清单。

现有 AGENT_WORKFLOW 第 13 节要求的三线状态和六个固定区块继续保留；本提案只改变其中“内容成果”的权重，不新增另一套状态汇报系统。

PI 不需要逐条审批常规抽取和格式修正，也不需要处理日常 Git、分支、CI 细节。遇到重大理论选择时，AI 必须给出中文解释、原文依据、例子和不同选择的后果。

## 10. 试点的衡量标准

不以 Issue 关闭数量、PR 数量、代码行数或测试数量作为主要绩效。

### 研究质量指标

- 来源主张是否能够逐条回溯；
- 案例推理链有多少步骤能够被来源重建；
- 是否保留了原文条件、例外、否定和时间层；
- 是否识别出足以推翻候选解释的反例；
- 新的跨星系/跨宫位结构是否有独立证据；
- 不能统一的地方是否被准确限定，而非强行统一。

### 工作效率指标

- 从开始研究到形成可接受知识成果所需的工作轮次；
- 每轮用于实际来源研究、案例重建和理论综合的比例；
- 因重复背景读取、重复建单和跨 lane 写集错误造成的返工；
- 宫位并行后等待时间和集成排队是否改善；
- PI 需要处理的常规管理事项是否减少。

### 试点成功条件

试点至少完成：
- 两个宫位检查点（若实时任务和依赖允许）；
- 一个 WP03/WP06A 案例重建研究检查点；
- 研究质量不下降，且没有增加跨宫位冲突或 PI 管理负担。

完成后由 AI 提交一页复盘：哪些调整有效、哪些无效、是否保留两个宫位槽位、Core 下一步是否继续案例/星系综合。

如果试点显示并行导致明显重复审查、写集冲突或质量下降，应恢复一个宫位槽位；不需要推翻整个内容优先研究模式。

## 12. 风险与回滚

| 风险 | 控制方式 |

| 两宫位并行造成跨宫位语义冲突 | 不共享未合并分支；共享语义只由 Core 处理 |

## 14. 本提案的边界声明

本提案获批只代表批准**研究路线、工作组织和有限并行试点**。

它不代表：
- 任何新的紫微斗数理论已经成立；
- 任何跨流派材料可以混用；
- 任何候选气核、应象或关系自动成为 canonical；
- 任何新 primitive、算子、概率、因果或经验参数获批；
- Product 获得新的知识消费或运行时权限；
- 经验预测有效性得到证明。

最终目标仍然是：以来源可追溯、条件完整、反例可检查的传统知识为基础，逐步建立能够重建作者推理过程、解释星曜与星系关系、处理宫位上下文和时间反应的理论体系。

**项目进度的首要单位应当是“新增了多少可靠的理解”，而不是“关闭了多少工单”。**
