# WP05 P12 Parents/Superiors Palace Semantic Boundary Audit

Status: **BOUNDARY_DEFINED — SOURCE GROUNDED**

## Scope
- palace: P12 父母宫
- canonical source: SRC-ZZ-003
- opening source span: printed pp177–178
- ontology baseline: parents; parent_relationship
- secondary scope: superiors; managers; supervising_institutions

## Source-defined semantic scope
The source explicitly gives P12 two separate scene families:

1. **parents/family-of-origin scene**
   - parent condition and relationship;
   - parental authority, protection and support;
   - separation / distance from parents;
   - family-structure complications;
   - parent mobility and, in high-specificity passages, illness or bereavement candidates.

2. **superior / manager / supervising-institution scene**
   - relationship with superiors;
   - authority and style of a manager;
   - stability or turnover of supervisors;
   - support, promotion pressure or conflict inside a supervising institution.

The source explicitly says that rules concerning Sun/Moon parent identification apply to the parent scene, while superior/manager interpretation should read the P12 star structure directly. Therefore the two scenes must never be silently collapsed.

## Hard boundaries

### P12 parent scene is not identical to superior scene
A single star configuration can project differently:
- as parent authority, closeness, separation or support;
- as manager authority, conflict, turnover or institutional environment.

Every normalized rule must preserve which scene is being used.

### Sun/Moon parent attribution is contextual
The chapter opening uses Taiyang/Taiyin dignity, transformation and day/night birth to refine father/mother interpretation, but explicitly requires the actual P12 star combination to be checked.

Therefore:
- Sun/Moon do not override the whole P12 configuration;
- a single Sun/Moon condition does not become a standalone deterministic death rule;
- parent-specific attribution is not reused for superior/manager interpretation.

### “刑克 / 孝服 / 灾病” remains fail-closed
The source contains many concrete predictions of parental injury, illness, death or mourning.

These are:
- EVENT_CANDIDATE;
- CASE_SUPPORT_ONLY when the claim is concrete/high-severity;
- never converted into a generic deterministic parent-mortality rule;
- always dependent on the exact source combination and, when temporal, the relevant annual/major-period context.

### Family structure must remain historical/contextual
Historical expressions such as:
- 重拜父母;
- 二姓延生;
- 偏房继室;
- 两重父母;
- 出祀 / 过继;
are preserved as auditable source scenes.

Modern normalization may describe separation, fostering/adoption, remarriage/step-parent or multiple-caregiver structures only when the source meaning supports it. It must not assume one modern family arrangement.

### Good stars do not automatically mean parental prestige
The source explicitly warns that 禄权科 in P12 do not necessarily mean “parents are prominent”; they may instead describe a superior/manager or merely indicate reduced parent-harm pressure.

### P12 strength must be checked against P01
Strong benefic P12 with weak P01 does not automatically mean the native benefits. The source requires actual “荫庇” support before concluding the native receives useful support; otherwise the configuration can describe dependency/subordination.

## Temporal / history policy
The source can contain explicit ordered relations such as:
- early separation -> later relationship structure;
- supervisor turnover -> later institutional relationship changes;
- a specified major-period trigger -> separation event.

Existing PATH_DEPENDENT_GATE is used only when the source explicitly encodes an ordered before→after dependency.

Literal period counts or age timing remain source evidence; they do not create new universal clocks.

## Epistemic policy
Parent death, illness, adoption/remarriage and similar high-specificity claims are preserved for audit but are not generalized beyond the source.

The knowledge system must distinguish:
- structural relationship rules;
- scene translation;
- timing triggers;
- concrete event candidates.
